# 派发与结果记录

实际委派任务时使用。只记录该任务适用的信息，已有任务卡可直接链接；不为只读分析或规划任务要求实现提交、独立工作树或测试环境。分工、写入权限和模型配置遵循技能正文及全局规则。

## 基本交接

- 派发时明确任务标识、负责人、目标与验收、输入或前置成果、交付物、操作范围及权限、停止条件、结果回报方式。涉及排期时说明预计交付时间；并行时说明独立交付边界、资源冲突检查和收益。
- 按任务类型补充：代码修改的基线版本、工作目录、共享文件负责人及集成约定，普通并行写入须隔离；测试的被测版本、环境、可用资源及禁止操作的共享现场；跨对话协作的主控和执行对话标识。只读任务标明禁止写入及所审查材料的版本或位置。阶段会话另按[阶段会话模式](stage-sessions.md)记录串行交接授权。
- 返回实际成果、结论与证据、未完成或未验证项、阻塞及下一步。涉及改动时补充修改范围和实际工作目录；确有提交时提供真实 SHA；运行检查时记录环境、版本和实际结果，不能把未运行记为通过。
- 主控核对结果，统一维护主计划，完成必要审查和集成后按正文的依赖条件放行。普通支线不直接修改主计划或共享目标分支；阶段负责人只在获准的检出目录和当前阶段范围内串行写入，仍不得修改总控主计划。

## Codex App 多对话操作

仅在使用 Codex App 的执行对话时读取本节；内部子代理使用当前代理工具，不因这里的工具名称自动创建用户可见对话。

- 普通模式由发起任务的当前会话主控；阶段模式中该会话为总控，新建会话仅负责其获准阶段，不继承总控的全局排期与签收权。只有用户明确要求新建执行对话时才使用 `create_thread`；普通并行授权不等于新建对话授权。用户明确要求新对话时，不以内部子代理替代。执行任务仍须满足正文的依赖、分工及权限条件。
- 优先继续使用已有的适用执行对话。仅在创建成功后登记真实对话 ID 和派发状态，失败时记录原因；创建成功不证明模型配置已生效，不能用提示词作为配置证明。接口不可用时报告限制，不擅自更换用户指定的执行方式或配置。
- 跨对话发送消息须有用户授权；授权不足时由主控读取结果。优先用 `wait_threads` 获取紧凑进度，必要时用 `read_thread` 获取详情，不能把发出任务、等待结束或对话空闲等同于验收完成。
- 执行对话只操作获授权范围；普通并行写入按正文隔离并由主控集成，阶段会话按阶段模式串行交接。共享现场按[现场协作](onsite-coordination.md)处理；暂停和恢复仍按技能正文执行。
