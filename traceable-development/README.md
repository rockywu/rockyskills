# 可追溯开发协作

Skill 名称：`traceable-development`。

用于编写和维护开发计划、任务、排期、进度与审查记录。通过稳定任务编号，把需求、依赖、验收证据、Git 提交和集成结果关联起来。

## 适用场景

- 将需求拆成可分工、可审查、可验收的开发任务。
- 判断任务的依赖是否满足，安排可以开始的工作。
- 跟踪计划日期、预计日期、实际日期和阻塞原因。
- 保存审查、验证、Git 与交接记录，便于恢复工作。

它不用于普通文案润色或无关文档写作，也不会自行提供任务管理服务、Git 自动化或后台调度。

## 使用示例

制定计划：

```text
$traceable-development
请读取现有需求和项目约定，制定本期开发计划。
每项任务写清目标、依赖、负责人和验收标准。
沿用已有文档结构，本次只做规划。
```

更新进度：

```text
$traceable-development
请核对当前文件、测试结果和 Git 记录，更新开发计划。
区分已经实现、已经验收、已经集成和已经部署的内容。
列出阻塞原因、下一步和现在可以开始的任务。
```

## 工作方式

先复用项目已有文档和流程，再按任务规模补充必要记录。小任务不强制创建整套文档。多个前置条件必须全部满足，提交代码不自动等于任务完成。

并行执行需要用户或项目授权，也需要环境支持。Skill 可以给出分工和启动顺序；实际是否启动、完成或发布，应以执行结果为准。

规则定义见 [SKILL.md](SKILL.md)，可选文档格式见 [最小文档模板](references/templates.md)，安装方法见 [仓库 README](../README.md)。
